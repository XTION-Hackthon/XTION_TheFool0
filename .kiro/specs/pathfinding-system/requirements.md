# 寻路系统需求文档

## 概述
实现基于 A* 算法的单房间寻路和多房间寻路系统，支持通过门洞跨房间导航。所有寻路操作由 agent 通过 API 调用驱动。

## 功能需求

### 1. 单房间 A* 寻路
- **1.1** 基于网格的 A* 算法实现
  - 网格大小：32px × 32px（与碰撞箱对齐）
  - 支持 8 方向移动（包括对角线）
  - 启发式函数：欧几里得距离
  
- **1.2** 障碍物处理
  - 墙体作为不可通行的网格
  - 门洞区域可通行
  - 其他 bot 作为动态障碍物
  
- **1.3** 路径平滑
  - 移除不必要的中间点
  - 直线路径优化

### 2. 多房间寻路
- **2.1** 房间图构建
  - 房间作为节点
  - 门洞作为边
  - 支持动态添加/删除房间和门洞
  
- **2.2** 跨房间路径规划
  - 先规划房间级别的路径
  - 再规划每个房间内的详细路径
  - 通过门洞中心点连接房间路径
  
- **2.3** 门洞通行验证
  - 检查门洞是否可通行
  - 验证房间容量限制

### 3. API 接口
- **3.1** 寻路 API 端点
  - `POST /api/pathfinding/move-to-target` - 移动 bot 到目标位置
  - 参数：botId, targetPos, targetRoomId
  - 返回：success, error
  
- **3.2** 客户端寻路 API
  - `GameScene.moveToTarget()` - 公开方法供外部调用
  - 执行完整的寻路和移动流程
  - 返回 Promise<{success, error}>

### 4. 性能要求
- **4.1** 单房间寻路 < 50ms
- **4.2** 多房间寻路 < 100ms
- **4.3** 支持 1000+ 网格的房间

## 非功能需求
- 内存高效：避免频繁分配大数组
- 可调试：支持路径可视化
- 容错性：无法到达时返回最接近的路径
- API 驱动：所有操作由 agent 通过 API 调用
